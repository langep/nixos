# Hyprland Lua migration handoff

## Why this was needed

After upgrading Hyprland, it began looking for `~/.config/hypr/hyprland.lua`.
The active Home Manager generation still provided the previous Hyprlang config
as `~/.config/hypr/hyprland.conf`, so Hyprland created a generic example Lua
config containing defaults such as Kitty and Dolphin.

The repository had deliberately pinned Home Manager to:

```nix
configType = "hyprlang";
```

because Lua support was previously immature.

## Changes made

`home/hyprland.nix` was migrated to the current Home Manager Lua API:

- `configType` changed from `"hyprlang"` to `"lua"`.
- Monitor and workspace strings became structured Lua API attributes.
- Hyprland settings moved below `settings.config`.
- Renamed settings use Lua-compatible names, such as `tap_to_click`.
- Existing bindings, autostart commands, screenshots, mouse operations, and the
  group-tabs submap were translated to `hl.bind`, `hl.dsp`, and `hl.on` calls.
- Existing per-host monitor/workspace behavior and Stylix colors were retained.

The user subsequently ran a rebuild. The NixOS system switch succeeded, but
Home Manager activation failed because Hyprland's autogenerated regular file
already occupied `~/.config/hypr/hyprland.lua`:

```text
Existing file '/home/langep/.config/hypr/hyprland.lua' would be clobbered
home-manager-langep.service: Failed
```

The autogenerated file was then preserved as:

```text
~/.config/hypr/hyprland.lua.generated
```

`~/.config/hypr/hyprland.lua` is now clear for Home Manager to create. Codex
did not run another rebuild or activation; the user will rebuild and reboot.

## Validation completed

- Nix evaluation reports `configType = "lua"` for both `desktop` and
  `thinkpad`.
- Home Manager evaluates a managed `hypr/hyprland.lua` file.
- `git diff --check` passes.
- The installed Hyprland parser was run against the evaluated Lua file with
  `Hyprland --verify-config`; the result was `config ok`.

## Rebuild

For the desktop:

```bash
sudo nixos-rebuild switch --flake .#desktop
```

The previous rebuild's system switch succeeded, but its Home Manager unit
failed due to the file collision described above. The next rebuild should be
able to complete Home Manager activation now that the conflicting file has
been moved aside.

## Checks after rebuild/reboot

1. Confirm `~/.config/hypr/hyprland.lua` is a Home Manager-managed symlink into
   the Nix store rather than the generic regular file Hyprland generated.
2. Confirm Home Manager activation succeeded:

   ```bash
   systemctl status home-manager-langep.service
   journalctl -b --no-pager -u home-manager-langep.service
   ```

3. Confirm the autogenerated-config warning is gone. If it remains, inspect
   the beginning of the active file and verify it does not contain
   `hl.config({ autogenerated = true })`.
4. Confirm monitors and persistent workspace assignments are correct.
5. Test focus/move, workspace, fullscreen/floating, screenshot, mouse
   move/resize, and group/group-tab bindings.
6. Confirm Mako, Waybar, and 1Password start automatically.
7. If startup fails, capture `journalctl --user -b` output and run:

   ```bash
   Hyprland --verify-config --config ~/.config/hypr/hyprland.lua
   ```

The relevant edits are currently uncommitted in `home/hyprland.nix`. Other
working-tree changes existed and should not be discarded while debugging.
